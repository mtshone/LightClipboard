## 30 秒了解这个项目

```
C# / .NET 10 / WPF (MVVM) + WPF-UI(Fluent) + LiteDB + H.NotifyIcon
        │
        ├─ 常驻托盘，Win+V / Ctrl+Shift+V 呼出面板，失焦自动隐藏（缓冲时长可调 50–1000ms）；关掉失焦隐藏后可开「始终置顶」，防止被同样置顶的窗口压住
        ├─ 可接管系统 Win+V：原生剪切板历史不再弹出，改用本面板
        ├─ 监听系统剪切板：文本 / Emoji / 图片(含 Win+Shift+S 截图) / 文件
        ├─ 图片落盘 PNG + 缩略图 LRU 缓存，历史按内容指纹去重
        ├─ 卡片可拖到桌面/资源管理器/Word/微信（FileDrop + Bitmap + PNG 三种格式），被接收后面板自动收起
        ├─ 图片可 Ctrl/Shift 多选（**仅图片**），拖动其中任意一张即把**整批**拖出（顺序：**有 Ctrl 参与 ⇒ 点击顺序**，**纯 Shift ⇒ 列表顺序**，v1.3.1），页脚显示「已选 N 张图片」（回归：`..\tools\multidrag-test.ps1`）
        ├─ 顶部一条主链：全部 → 文本 → 图片 → 文件 → 😀 Emoji → ⭐ → 设置（收藏项只在 ⭐ 里）
        ├─ 点击卡片 = 复制 + 自动切回原窗口模拟 Ctrl+V；**剪切板只借一次**，粘贴送达后自动还原
        └─ 列表顺序 = 收录顺序：输出（复制 / 粘贴 / 拖出）不会把卡片顶到最上面；
           正常情形下系统剪切板内容 ≡ 列表顶部那条（按 Ctrl+V 拿到的通常是它）
```

规模：36 个文件（30 个 `.cs` + 3 个 `.xaml` + `LightClipboard.csproj` + `app.manifest` + `Assets/app.ico`），
其中文本文件 35 个、共 8615 行（不含空行，不含 bin、obj、二进制图标不计行）；
内置 110 项无界面自检（13 组）、110/110 通过。当前版本 **v1.3.1**。
本次发布包 = `LightClipboard-v1.3.1-win-x64.zip`（**框架依赖单文件**，exe 8,331,344 字节 ≈ 8.33 MB，
**目标机需先装 .NET 10 Desktop Runtime**；对照：自包含单文件 64,728,470 字节 ≈ 61.73 MB），
发布命令与包内条目见 [07-构建发布与测试.md](07-构建发布与测试.md) 第 2 节的 v1.3.1 实操记录。

## 三条最省时间的上手路径

**只想知道怎么跑起来**
```powershell
cd <仓库根>\src\LightClipboard
dotnet build -c Release    # 改完代码务必重建 Release（别运行旧产物！）
dotnet run                 # 弹出面板（Debug）
dotnet run -- --selftest   # 110 项自检，退出码 0 表示全部通过
```

**想改某个功能** → 直接看 [02-源码导读.md](02-源码导读.md) 的「常见需求 → 改动落点」表。

**改剪切板读取、图片处理、拖拽或面板显隐前** → 先看 [04-实现细节与坑点.md](04-实现细节与坑点.md)，
里面的每一条都是真机上踩过的坑，且大部分已加自检回归保护。

**想动"支持管理员权限窗口"这件事** → 先看 [10-高权限窗口支持决策记录.md](10-高权限窗口支持决策记录.md)，
里面已有实测结论，别重复踩一遍。

## 维护本资料库的约定

- 新增/修改功能后，同步更新：CHANGELOG、相关专题文档；**改了坑点相关代码必须更新 04**。
- 文档里的文件路径、常量值、行数如与源码不符，以源码为准，并顺手修正文档。
- 新增专题文档按 `NN-主题.md` 顺延编号（当前已用 `10`；`00`/`09` 保留给需求方原文，`CHANGELOG.md` 不编号）。
- 只改代码不改文档时，至少在 CHANGELOG 留一条记录；**验收结论要写清楚"哪些是脚本验的、哪些是真机手验的"**，
  避免下次把"脚本没覆盖"误判成"功能没生效"（v1.1.0 就发生过一次：实际是运行了旧 exe）。
- 涉及**未采纳的架构方案**时，把"为什么不采纳"一并记进 `10-*` 决策记录，别只在对话里说过就算。
