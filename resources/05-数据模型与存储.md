# 05 · 数据模型与存储

## 1. 存储介质总览

| 内容 | 位置 | 形式 |
| --- | --- | --- |
| 历史记录（文本、元数据、指纹） | `%LocalAppData%\LightClipboard\clipboard.db` | LiteDB 单文件 |
| 图片本体 | `%LocalAppData%\LightClipboard\Images\yyyy-MM\<hash前24位>.png` | PNG 文件 |
| 拖拽导出文件 | `%LocalAppData%\LightClipboard\Exports\<同名>.png` | PNG 文件（供外部程序读取） |
| 用户设置 | `%LocalAppData%\LightClipboard\settings.json` | JSON |
| 运行日志 | `%LocalAppData%\LightClipboard\Logs\app-yyyyMMdd.log` | 文本，保留 14 天 |
| 自检报告 | `%TEMP%\LightClipboard-SelfTest\Logs\selftest.txt`（自检模式专用目录） | 文本 |

数据根目录由 `Services/AppPaths.cs` 决定，可用环境变量 `LIGHTCLIPBOARD_HOME` 整体重定向
（`--demo` 与 `tools/` 下的自动化脚本正是用它隔离数据，避免污染真实历史）。
注意 **`--selftest` 不读这个变量**：它强制把数据目录指向 `%TEMP%\LightClipboard-SelfTest`（见 `App.xaml.cs`），
所以"设了变量就一定隔离"只对演示/自定义运行成立。

## 2. LiteDB 集合 `items`

模型：`Models/ClipboardItem.cs`。`Id` 映射为 LiteDB 的 `_id`（自增 int）。

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `Id` | int | 主键 | 自增 |
| `Type` | int(枚举) | 0=Text 1=Image 2=Files | **显式赋值，不可调序**（已落库的是数字） |
| `Hash` | string | 内容指纹（SHA-256 十六进制，64 字符） | 去重键，已建索引 |
| `Text` | string? | 文本内容 | 超过 `MaxTextLength` 在解析阶段截断 |
| `ImagePath` | string? | PNG 绝对路径 | 图片已删除时该路径可能失效，读取方需容错 |
| `ImageWidth` / `ImageHeight` | int | 像素尺寸 | 卡片标题显示用 |
| `ByteSize` | long | 文本为 UTF-8 字节数；图片为 PNG 文件长度；文件为文件大小之和 | |
| `FilePaths` | List\<string\> | 文件条目路径集合 | |
| `SourceApp` | string | 来源进程名（尽力而为，可能为空） | 通过前台窗口进程名获取 |
| `CreatedAt` | DateTime | 首次入库时间 | |
| `LastUsedAt` | DateTime | 最近一次复制/使用时间 | 排序键，已建索引 |
| `IsPinned` | bool | 是否收藏 | 已建索引；收藏项不参与裁剪且始终置顶 |

索引：`Hash`、`LastUsedAt`、`IsPinned`。

### 2.1 内容指纹算法

| 类型 | 算法 | 位置 |
| --- | --- | --- |
| 文本 | `SHA256(UTF8(text))` | `ClipboardWriter.ComputeTextHash` |
| 文件 | `SHA256(小写化路径按 \n 连接)` | `ClipboardWriter.ComputeFilesHash` |
| 图片 | `SHA256(PNG 字节)` —— 即先编码再哈希，`Hash` 同时就是文件名前缀 | `ImageCacheManager.SavePng` |

图片用"编码后哈希"，好处是：**文件名即指纹**，同一张图重复复制不会产生第二份文件。

### 2.2 去重语义（`StorageService.AddOrTouch`）

```
存在同 Hash 记录？
├─ 是 → 更新 LastUsedAt = now；Text 类型顺带刷新 Text；SourceApp 非空则覆盖；
│        返回 (已存在实体, isNew: false)
└─ 否 → Insert，返回 (新实体, isNew: true)
```

界面侧（`MainViewModel.ApplyToView` / `SyncVisible`）据此把卡片**移动到列表顶部**而不是插入重复卡片。
排序规则：`IsPinned` 降序 → `LastUsedAt` 降序。

### 2.3 裁剪与清理

| 时机 | 动作 | 位置 |
| --- | --- | --- |
| 每次入库后 | `Prune(MaxItems)`：非收藏记录按 `LastUsedAt` 保留最新 N 条，其余删除并**同时删除对应 PNG 文件** | `MainViewModel.TrimToLimit` |
| 启动时 | 再次 `Prune` + `CollectGarbage` 清理无引用的孤儿 PNG 与 7 天前的导出文件 | `AppHost.RunStartupMaintenance` |
| 清空历史 | `Clear(keepPinned: true)`，删除被删记录的图片文件，然后 `Shrink()`（内部调用 LiteDB 的 `Rebuild()`）压缩数据库 | `MainViewModel.ClearAll` |
| 删除单条 | `Delete(id)` + 删除对应图片 | `MainViewModel.Delete` |

## 3. 图片文件命名与生命周期

```
Images/2026-09/3e4d2a03f23e84bc20c26ce9.png     ← SHA-256 前 24 位
Exports/3e4d2a03f23e84bc20c26ce9.png           ← 拖拽时按同名复制一份，7 天后清理
```

- 落盘路径按"年-月"分目录，避免单目录文件过多。
- 写入采用"先写 `.tmp` 再 `File.Move` 覆盖"，避免半个文件。
- `Exports` 存在的意义：拖给资源管理器/微信/QQ 时需要一个**稳定的文件路径**，
  且同一张图重复拖拽应指向同一文件（内容哈希保证）。

## 4. settings.json 全字段

模型：`Services/AppSettings.cs`。**取值范围有三道钳制**，修改时注意别只看一处：

| 位置 | 作用 |
| --- | --- |
| `Views/MainWindow.xaml`（设置页滑块） | 界面可达范围：`MaxItems` 50–1000 |
| `ViewModels/MainViewModel`（属性 setter） | 二次钳制：`MaxItems` 20–2000 |
| `Services/SettingsService.Normalize` | 落盘/加载时的最终钳制（下表所列） |

| 字段 | 默认值 | 落盘钳制范围 | 说明 |
| --- | --- | --- | --- |
| `MaxItems` | 300 | 20–5000（界面实际 50–1000） | 历史条数上限（不含收藏） |
| `MaxTextLength` | 100000 | 1000–2000000 | 单条文本最大字符数 |
| `HotkeyEnabled` | true | — | 是否注册全局热键 |
| `EnableWinVHook` | true | — | 是否用低级键盘钩子接管系统 Win+V（旧 settings.json 无此字段时按 true 生效） |
| `AutoPaste` | true | — | 点击卡片后自动粘贴 |
| `HideOnDeactivate` | true | — | 失焦自动隐藏 |
| `DeferredHideDelayMs` | 700 | 50–1000 | 失焦后的隐藏缓冲时长（ms）；设置页「隐藏延迟」滑块 + 手动输入（旧 settings.json 无此字段时按 700 生效） |
| `RunAtStartup` | false | — | 开机自启（真实状态以注册表为准） |
| `Theme` | Dark(2) | 枚举 | 0=跟随系统 1=浅色 2=深色 |
| `ThumbnailWidth` | 320 | 96–1024 | 缩略图解码宽度 |
| `CopyImageWithFilePath` | false | — | 复制图片时是否附带文件路径格式 |
| `MonitorPaused` | false | — | 暂停监听（不写入新记录） |
| `WindowWidth` / `WindowHeight` | 0 | 0 或 380–2000 / 420–2000 | 0 表示用 XAML 默认值（470×700） |

写入策略：整体序列化到临时文件后 `File.Move(overwrite: true)`；
保存时机为设置项变更、面板收起（记尺寸）、程序退出。

## 5. 数据兼容与迁移

- LiteDB 采用 `Connection=Shared`、`Upgrade=true`，同版本内可平滑升级。
- **新增字段**：直接加到 `ClipboardItem` 即可，旧记录反序列化时字段取默认值（`Type` 默认 0=Text 需留意）。
- **删除/重命名字段**：旧数据会静默丢失该字段，需自行做一次性迁移（读全部 → 转换 → `Update`）。
- **枚举值不可复用**：`ClipboardItemType` 的数字已落库，新增类型只能往后追加。
- **settings.json 新增字段**：`System.Text.Json` 只为 JSON 里出现的属性赋值，缺失的字段保留 C# 属性初始值 ——
  也就是说**加一个新设置项等于立刻改变了所有老用户的默认行为**。加之前先想清楚这个默认值是否合适
  （例：`EnableWinVHook` 默认 `true`，老用户升级到 v1.1.0 后 Win+V 会立刻被接管；
  若希望"新功能默认关闭"，把默认值写成 `false` 即可）。
- 升级 LiteDB 大版本前请备份 `clipboard.db`，并用 `--selftest` 验证读写。

## 6. 备份、恢复与排障

| 场景 | 做法 |
| --- | --- |
| 备份全部资料 | 复制整个 `%LocalAppData%\LightClipboard` 目录（数据库与图片都在里面） |
| 只备份文字历史 | 复制 `clipboard.db`（图片会缺，卡片会显示占位） |
| 数据库疑似损坏 | 删除 `clipboard.db` 后重启（图片文件会成为孤儿，下次启动被 `CollectGarbage` 清理） |
| 磁盘占用过大 | 调小 `MaxItems`；或删除 `Images` 目录下较旧的月份目录后重启 |
| 想看程序做了什么 | `Logs\app-yyyyMMdd.log`；级别是定长 5 字符，检索用 `Select-String '\[WARN'` 或 `'\[ERROR'` |

## 7. 数据量参考

- 单条文本记录 ≈ 0.5–2 KB（视文本长度）。
- 图片记录：数据库里只有路径，占几十字节；磁盘占用等于 PNG 体积（1080p 截图 ≈ 150–400 KB）。
- 默认上限 300 条 + 30 天不清理策略下，典型占用在几十 MB 量级。
