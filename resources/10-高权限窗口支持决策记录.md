# 10 · 高权限（管理员）前台窗口的支持决策记录

> **状态：暂缓（已知边界，未修改架构）** —— 2026-09-19 记录，等后续决策。
> 触发场景：Everything（`run_as_admin=1`）里按 Win+V 弹出的是**系统原生剪切板**、拖文件进面板会中途隐藏。

## 1. 现象（用户报告）

| 场景 | 期望 | 实际 |
| --- | --- | --- |
| 在 **Everything** 里按 `Win+V` | 弹出 LightClipboard 面板 | 弹出**系统原生剪切板历史**，本面板毫无反应 |
| 从 **Everything** 拖文件到面板上 | 面板保持可见、可接收拖放 | 面板中途**失焦隐藏**，永远拖不进去 |
| 从 Edge / 资源管理器 做同样操作 | — | **一切正常** |

关键线索：**只在 Everything 上复现**。这排除了"拖拽/钩子实现本身有 bug"，指向两个程序之间的差异。

## 2. 定位过程（可复现）

### 第 0 步：查环境差异

```
<Everything 安装目录>\Everything.ini      ← 即 Everything.exe 同目录下的配置文件
    run_as_admin=1          ← Everything 以管理员权限运行
```

对比完整性级别（IL）实测：

| 进程 | 完整性级别 |
| --- | --- |
| `explorer.exe`（本机） | HIGH（0x2000） |
| `Everything.exe`（GUI） | HIGH（0x2000） |
| `LightClipboard.exe`（普通方式启动） | **MEDIUM（0x1000）** |

> 注意：本机 explorer 本身是提权的，所以"MEDIUM 前台"这种理想对照组在这台机器上很难造出来 ——
> 这也是下面第 3 步必须自建探针的原因。

### 第 1 步：给应用加诊断日志

在 `KeyboardHookService.RaiseWinVPressed` 里打印「本进程完整性 / 当前前台窗口（类名+PID+标题）」，
并在 `MainWindow` 的 `Deactivated` / `DragEnter` / `DragOver` / `DragLeave` / `Drop` 各打一行。

**结果**：Everything 在前台时，按 Win+V **日志里连"拦截到 Win+V"都没有** ——
说明钩子回调压根没被调用；而面板窗口本身是"已显示"状态（`--hidden` 启动时并未显示）。
另外抢焦点路径会记 `面板未能取得前台焦点（前台窗口可能以管理员权限运行）`。

### 第 2 步：自建独立探针（关键）

应用本身变量太多，于是写了一个最小探针 `HookProbe.exe`（约 200 行）：

- 挂 `WH_KEYBOARD_LL`，把收到的每次按键（vk / 注入标志 / Win 是否按下 / **当前前台窗口类名**）写日志；
- 自建一个真实顶层窗口，用来"让探针自己当靶子"（构造同级前台这个对照组）；
- 用 `SetTimer` → `PostQuitMessage` 结束消息泵（低级钩子回调必须在**正在泵消息的线程**上派发，
  最初只 `PeekMessage`、"泵"得不对，导致一条按键都收不到 —— 探针自身的坑，记在这里免得重踩）。

**同一份探针，只换前台窗口，做 A/B/C 三组对照**（注入真实的 Win+V 按下/抬起序列）：

| 用例 | 前台窗口 | 前台 IL | 钩子进程 IL | 钩子是否收到按键 |
| --- | --- | --- | --- | --- |
| A | 探针自有窗口 | HIGH | HIGH | ✅ 收到 4 个事件（含 V 键 2 个） |
| B | **Everything** | HIGH | MEDIUM | ❌ **一个都没收到** |
| C | Everything 最小化后 | — | MEDIUM | ✅ 恢复收到 |

**结论**：不是"钩子没装好"，也不是"判定逻辑写错"，而是**钩子回调被系统丢弃了**；
且丢弃条件与前台窗口的完整性级别直接相关（B ↔ C 只差"Everything 是不是前台"）。

### 第 3 步：排除"全局热键"替代方案

既然低级钩子被 UIPI 挡住，自然会想"那就别用钩子了，改用 `RegisterHotKey(MOD_WIN, V)` ——
热键是发给注册窗口的消息，不受前台窗口完整性影响"。实测：

| 试验 | 结果 |
| --- | --- |
| MEDIUM 进程 `RegisterHotKey(MOD_WIN\|MOD_NOREPEAT, 'V')` | ❌ **FAIL，err=1409 `ERROR_HOTKEY_ALREADY_REGISTERED`** |
| 同一进程注册两次（自检对照） | 第二次也是 1409（确认 API 行为正常） |
| 查注册表 `HKCU\Software\Microsoft\Clipboard` | `EnableClipboardHistory=1`、`ShellHotKeyUsed=1` |
| 临时把 `EnableClipboardHistory` 置 0 + 重启 explorer 后再注册 | ❌ 仍被占用（`ShellHotKeyUsed` 仍为 1） |

即：**Win+V 这个热键已经被 Shell 的原生剪切板历史占用**，"改用热键"此路不通
（除非让用户关掉原生剪切板历史并重新登录，代价是彻底失去该功能，且本机未能通过重启 explorer 验证成功）。

## 3. 根因（一句话）

> **Windows 的 UIPI：低完整性级别的进程，其低级键盘钩子（`WH_KEYBOARD_LL`）回调会被系统直接丢弃。**

- "低级"指的是钩子类型（在键盘输入进入任何窗口消息队列**之前**拦截），**不代表它不受完整性检查约束**；
- 前台窗口的完整性级别**高于**钩子进程时，该进程的钩子回调不再被调用 —— 不报错、不抛异常、静默失效；
- 于是 `Win+V` 原样落给 Shell → 系统原生剪切板历史响应 → 用户看到"弹的是系统面板"。

同一机制还解释了两个连带现象：

1. **抢焦点失败**：MEDIUM 进程无法从 HIGH 前台窗口手里拿到前台焦点
   （`SetForegroundWindow` / `AttachThreadInput` 兜底都受 UIPI 限制），
   所以即便钩子能命中，面板也会"浮在最上层但打不了字"。
2. **拖拽中断**：拖拽起点（Everything）失焦本窗口 → 本窗口想隐藏/被隐藏后无法再抢回前台 →
   光标移到面板位置时窗口已经不见了，`DragEnter` 永远不触发。

**边界补充**：这也意味着"以管理员身份运行本程序"**不是**解法 ——
那样确实能接管提权窗口，但反过来会让本程序无法与普通权限程序交互剪切板（见坑点 12），
属于按下葫芦浮起瓢。

## 4. 候选方案与代价评估

| 方案 | 做法 | 效果 | 代价 / 风险 | 评价 |
| --- | --- | --- | --- | --- |
| **A. 让该程序不再提权** | Everything 选项里取消"以管理员身份运行" | ✅ 立即恢复（同级前台，钩子正常） | 零代码改动；但 Everything 读 USN/日志受限，**部分系统位置索引不到**（用户可感知的功能损失） | **零成本，首选规避**；已写入 README「已知限制」 |
| **B. 提权钩子伴随进程（业界标准）** | 主程序保持普通权限 + 新增一个**以管理员权限常驻的轻量钩子进程**，由它装钩子并通过 IPC 通知主程序唤起面板 | ✅ 能覆盖提权窗口的 Win+V | **架构级改动**：新增进程/生命周期/单实例/崩溃重启/IPC 协议/版本一致性；首次启动需一次 UAC；安装包与开机自启逻辑都要改 | 技术上可行，是 ClipboardFusion / Ditto 一类工具的做法；本次**未采纳** |
| **C. 放弃钩子，关掉原生剪切板历史后注册热键** | 引导用户关闭 `EnableClipboardHistory` → `RegisterHotKey(Win+V)` 可用 | ✅ 不受 UIPI 限制 | ❌ 用户**永久失去**系统原生剪切板历史；本机实测"置 0 + 重启 explorer"后热键仍被占用（需重新登录才可能释放，未验证成功）；改动用户系统设置，侵入性强 | **不推荐** |
| **D. 维持现状 + 文档化** | 不改代码，把边界与规避方式写清楚 | 普通窗口全部正常；提权窗口退化为系统原生行为 | 无 | **本次采纳**（等后续决策） |
| E. 只在托盘/设置页做提示 | 检测到前台窗口提权时给一次性提示 | 降低困惑 | 需要持续轮询前台窗口，收益有限 | 可作为 A/D 的补充 |

**架构冲突判断**（回答"加这个支持会不会和现有架构冲突"）：
方案 A、D、E **不冲突**；方案 B **有实质冲突** ——
现有设计是"单进程 + 一个 HWND 承载全部系统集成"（见 [01-架构设计.md](01-架构设计.md) §5），
而 B 必须引入第二个进程与一套 IPC，并重新定义"哪个进程负责托盘/热键/钩子/开机自启"。

## 5. 当前决定

**暂缓**（用户 2026-09-19 决策）：先只做 v1.2.0 的两项需求（隐藏延迟可调、顶部导航改版），
Everything 问题按"已知边界"记录，不做架构改动。

**给用户的实际建议**：如果需要在 Everything 里用 Win+V，**把 Everything 的"以管理员身份运行"关掉**
（选项 → 常规 → 取消勾选；或把 `Everything.ini` 的 `run_as_admin` 改为 0）。

## 6. 若将来要做（方案 B 的落地要点）

1. **只把钩子搬出去**：伴随进程职责越单一越好 —— 挂 `WH_KEYBOARD_LL` → 命中 Win+V → IPC 通知主程序；
   托盘、热键、剪切板监听、存储全部留在主程序。
2. **IPC 选型**：命名管道（`NamedPipeServerStream`，可设 `PipeSecurity` 只允许本用户）或
   `WM_COPYDATA`。消息体只需"一个事件"，不需要传数据。
3. **生命周期**：伴随进程崩溃要能被主程序发现并重启；主程序退出要回收它；
   两者都要在"任务管理器里能看出是一对"（进程名建议 `LightClipboard.HookHost.exe`）。
4. **UAC 一次**：通过计划任务（`RunLevel=Highest` + 登录触发）或首次启动时 `runas` 提权；
   注意"以管理员运行"的伴随进程**无法**被普通权限主程序 `SetForegroundWindow` 直接指挥，
   但"通知主程序去显示面板"这条链路是主程序自己抢焦点，仍需面对 UIPI ——
   **即方案 B 只能解决"拦截"，不能解决"抢焦点"**。若还要求能打字，
   要么把面板也放进提权进程（那就等于整体提权，回到坑点 12 的问题），要么接受"面板弹出但需手动点一下"。
   > ⚠️ 这一条是方案 B 最容易被低估的部分，动手前务必先做技术验证。
5. **验收**：`tools/winv-test.ps1` 需要扩展出"提权前台窗口"用例；
   前置条件是本机能稳定构造出 MEDIUM 前台窗口（本机 explorer 是提权的，需要额外手段）。

## 7. 附：本次用过的实测手段（可复用）

| 手段 | 作用 | 备注 |
| --- | --- | --- |
| 最小 `HookProbe.exe` | 隔离验证"钩子到底有没有被调用" | 关键点：钩子回调必须在**正在泵消息**的线程上派发；自建真实窗口才能构造"同级前台"对照 |
| 应用内诊断日志 | 看应用视角的钩子命中与前台窗口 | 本次为临时改动，验收后已全部清理（源码无 `[DIAG]` 残留） |
| `GetTokenInformation(TokenIntegrityLevel)` | 读进程完整性级别 | 用子授权项 RID 判断：`0x1000`=MEDIUM、`0x2000`=HIGH、`0x3000`=SYSTEM |
| `CreateProcessAsUser` + 复制主令牌后改 IL | 造 MEDIUM 进程 | ⚠️ 若用 `CreateRestrictedToken`（受限令牌）启动，**该进程的全局钩子会失效**，会得出错误结论 —— 本次就踩过，务必用"完整令牌 + 只降 IL"的方式 |
| 临时把 `EnableClipboardHistory` 置 0 + 重启 explorer | 验证热键占用来源 | 试验后必须还原原值（本次已还原为 1） |

> 这些脚本与探针都是一次性排障工具，**没有留在 `tools/` 里**；
> 需要重做时按上表重新搭即可（约 200 行 C# + 几个 PowerShell 脚本）。
