# 07 · 构建、发布与测试

## 1. 常用命令

```powershell
cd <仓库根>\src\LightClipboard

dotnet build                       # 调试构建
dotnet run                         # 运行并弹出面板
dotnet run -- --hidden             # 只驻留托盘
dotnet run -- --demo               # 写入演示数据（配合隔离目录）
dotnet run -- --selftest           # 110 项无界面自检，退出码 0/1

dotnet build -c Release            # 重建 Release（运行 bin\Release\...\LightClipboard.exe 前必做）
dotnet publish -c Release          # 单文件自包含发布（默认）
```

命令行参数与环境变量见项目根 `README.md`。

## 2. 发布方式对比（实测）

| 方式 | 命令 | 体积 | 空载工作集 |
| --- | --- | --- | --- |
| **单文件自包含**（默认） | `dotnet publish -c Release` | 单个 exe 61.73 MB（v1.3.1 / v1.3.0 实测 64,728,470 字节；v1.1.0 为 61.71 MB） | ≈260 MB（v1.1.0 实测） |
| 自包含多文件 | `dotnet publish -c Release -p:PublishSingleFile=false` | 目录 ≈150 MB | ≈150 MB（v1.0.1 实测） |
| 框架依赖 | `dotnet publish -c Release -p:SelfContained=false -p:PublishSingleFile=false` | 数 MB | ≈120 MB（v1.0.1 实测） |
| **框架依赖单文件**（v1.2.4 / v1.3.0 / v1.3.1 的发布包用它） | `dotnet publish -c Release -p:SelfContained=false -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=false` | 单个 exe **8.33 MB**（v1.3.1 实测 8,331,344 字节；v1.3.0 实测 8,327,248 字节；v1.2.4 为 8.31 MB / 8,319,056 字节）（需 .NET 10 桌面运行时） | 未实测（同"框架依赖"档量级） |

> **框架依赖单文件必须覆写 `EnableCompressionInSingleFile=false`**（真机踩到）：csproj 的 Release 段是按
> "单文件**自包含**"配的（`SelfContained=true` + `PublishSingleFile=true` + `EnableCompressionInSingleFile=true`），
> 而**单文件压缩只支持自包含**，直接发框架依赖单文件会构建失败：
> `error NETSDK1176: 仅在发布独立应用程序时才支持在单个文件捆绑包中进行压缩`。
> `IncludeNativeLibrariesForSelfExtract` 不必动（对框架依赖无影响；实测加不加产物都是 8,319,056 字节）。
> 发布包形态（v1.3.1 起）：`LightClipboard-v<版本>-win-x64.zip`（命名口径 = **程序名 + 版本 + 系统 + 架构**），
> **两个条目**、扁平放根目录：`LightClipboard.exe` + `README.md`（README 里要写明目标机需先装
> .NET 10 **桌面**运行时）。v1.3.0 的包名带 `-net10` 后缀、另含一页《安装与运行说明.txt》（三个条目），
> 见下面的 v1.3.0 历史记录。
>
> v1.3.0 实操记录：zip = `LightClipboard-v1.3.0-win-x64-net10.zip`（三个条目，扁平放根目录），
> 用上面"框架依赖单文件"那条命令发布（**加 `-o` 指定独立目录**，避免覆盖自包含产物目录）；
> 《安装与运行说明.txt》的源文件在仓库里（`tools\release\安装与运行说明.txt`），打包时直接复制进去 ——
> 这样发布物里的说明与仓库版本可追溯，不再是一次性手写的。包内 exe 已用 `--selftest` 与
> `--demo` 启动各验一次（102/102 通过、8 张演示卡片正常）。
>
> **v1.3.1 实操记录**：发布命令 =
> `dotnet publish -c Release -p:SelfContained=false -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=false -o <独立目录>`
> （**加 `-o` 指向独立目录**，不覆盖 `bin\Release\net10.0-windows\win-x64\publish\` 里的自包含产物）；
> 产物 `LightClipboard.exe` = **8,331,344 字节**（≈ 8.33 MB，`FileVersion 1.3.1.0` / `ProductVersion 1.3.1`）。
> 打包为 `LightClipboard-v1.3.1-win-x64.zip` = **3,479,386 字节**（≈ 3.32 MiB），
> **两个条目、扁平放根目录**：`LightClipboard.exe` + `README.md` —— 按用户要求**没有**放
> 《安装与运行说明.txt》，所以包内 `README.md` 里那句「目标机需先装 .NET 10 Desktop Runtime（x64）」
> 就是用户拿到包后唯一的前提说明。
> 包内 exe 解压后复验：`LightClipboard.exe --selftest` → **通过 110 项、失败 0 项**、退出码 0。
> 体积对照（同为本次发布版本）：**自包含**单文件 = 64,728,470 字节（≈ 61.73 MB），框架依赖单文件 =
> 8,331,344 字节 —— 差出来的部分就是「目标机自己装运行时」换来的。
> 分发前提：目标机需先装 **.NET 10 Desktop Runtime（x64）**，下载
> <https://dotnet.microsoft.com/download/dotnet/10.0>（选「.NET Desktop Runtime 10.x → x64」）。

产物路径：`bin\Release\net10.0-windows\win-x64\publish\LightClipboard.exe`
（框架依赖单文件那次发布若用了 `-o <目录>`，产物就在该目录下，**不会**覆盖上面这个自包含产物目录）

> 发布后**务必核对产物版本号**（`(Get-Item ...\publish\LightClipboard.exe).VersionInfo.FileVersion` 应为当前版本）——
> v1.1.0 开发时就出现过"源码已改、publish 目录仍是上一版"的情况，直接分发会得到没有新功能的 exe。
> 内存实测方法与口径见项目根 `README.md` 的「发布方式与内存占用」一节。

> **重建 Release 前要先退出正在运行的程序**：否则 `LightClipboard.exe` 被自身进程占用，
> 构建会在 `MSB3026/MSB3027` 上重试 10 次后失败（错误信息是"文件被 LightClipboard (pid) 锁定"）。
> 这不是代码问题，`taskkill /IM LightClipboard.exe /F` 或托盘退出后重试即可。

单文件模式内存偏高的原因见 [04-实现细节与坑点.md](04-实现细节与坑点.md) 第 10 条。

## 3. 无界面自检（`--selftest`）

报告位置：`%TEMP%\LightClipboard-SelfTest\Logs\selftest.txt`（自检强制使用隔离数据目录，
不会污染 `%LocalAppData%\LightClipboard` 里的真实数据）。退出码 0 = 全部通过。

覆盖 **110 项**断言，分 13 组：

**目录布局（4）**：数据根目录 / 图片缓存目录 / 导出目录 / 日志目录均创建成功。

**设置持久化（4）**：`MaxItems`、`AutoPaste`、`始终置顶`、`Theme` 写入后重新加载一致。

**LiteDB 存储（9）**：新建数据库；插入记录；相同内容去重（计数仍为 1）；收藏标记；
查询返回记录；批量写入 9 条；超限裁剪（8 条非收藏裁到 3 条 → 删 5 剩 4）；收藏项未被裁剪；删除单条。

**输出（复制 / 粘贴）不改变历史排序位置（6）**：装载顺序 = 最近入库倒序；输出确实发生（内容写入剪切板）；
输出后卡片没有被移到最前；输出后排序键（`LastUsedAt`）未被改写；
**反向对照**：再次收录相同内容仍刷新排序键、该条按新时间排到最前（证明"顺序不变"不是把排序写死了）。
用的是真实 `MainViewModel` + 临时 LiteDB，点的是列表**最下面**那条 —— 改动前它会跳到最前。

**输出后剪切板还原（借一次就还）（22）**（v1.2.4）：装载顺序 = 最近入库倒序（输出前那份在列表顶部）；
前置剪切板 = 顶部那条；点**第二条**（自动粘贴）后输出确实发生（剪切板被借走、写的是被点的那条）、
列表顺序不变、有待还原的快照；`RestoreNow()` 后**剪切板 = 输出前的内容**（按 Ctrl+V 得到列表顶部那条）、
不是被输出的那条、列表顺序仍不变、没有残留快照；
**反向对照**：关掉自动粘贴（只复制路径）后内容留在剪切板里、不建立快照，"无快照时还原是空操作"（不会清空剪切板）；
多格式：HTML Format 这类字节型格式**逐字节一致**（Win32 原始 HGLOBAL 读回比对）；
图片：位图与 PNG 流两条载荷都能带走（还原后 `GetImage()` 尺寸一致、PNG 流逐字节一致）——
最后这条是"真机端到端先抓到 `InvalidCastException`、自检后补"的回归保护。

**图片缓存与缩略图（12）**：PNG 落盘；哈希长度 64；文件大小 > 0；PNG magic number 正确；
相同图片复用同一文件；缩略图可解码；缩略图已按宽度缩放（≤320）；缩略图已冻结；
原图可加载（宽度 1920）；拖拽导出文件生成；删除图片文件；缩略图缓存可清理。

**剪切板读写（10）**：写入文本；自身写入被标记为屏蔽（防死循环）；读回文本一致（含 Emoji）；
解析器识别文本类型；解析器保留 Emoji 原样；写入图片；解析器识别图片类型；读回图片尺寸一致；
DIB 回读后 alpha 修正为不透明；**规范化后的剪切板图片可在后台线程编码**。

**拖拽数据对象（6）**：图片条目可构造拖拽数据；包含 FileDrop；包含 Bitmap；包含 PNG；
FileDrop 指向真实存在的 PNG；文本条目包含 UnicodeText。

**多选拖拽：多张图片的数据对象（7）**（v1.3.0）：数据对象可构造；包含 `FileDrop`；路径数量正确；
每个路径都**真实存在**；**顺序与传入一致**；非图片条目被跳过；无可用图片时返回 `null`。

**多选状态机（ClipboardSelection）（24）**（v1.3.0；顺序口径 v1.3.1 修订）：Ctrl 加入与取消；**非图片被拒绝且不改动选择**；
普通单击清空；Shift 范围跨文本只选图片；Shift 跨到末张（文本与文件被跳过）；**连续 Shift 锚点不动**；
锚点被取消后回退到剩余已选项；`Reset` 清空；`Insert` 不清空；拖拽队列长度 = 已选图片数；队列只含图片；
**Ctrl 点击顺序 = 输出顺序（4→2→0 ⇒ image4,image2,image0）**；**取消后重新 Ctrl 选中 ⇒ 排到队列末尾**；
**Ctrl 参与过之后 Shift 只做末尾追加（已在队列里的项不重排、不取消）**；**纯 Shift 区间 ⇒ 列表升序，且再 Shift 回更小区间时整体替换、收缩**；
选中项文件缺失静默跳过；选中项被单条移除后队列不丢项、不重复；`Changed` 事件。
这两组是**纯逻辑**用例：`ClipboardSelection` 只依赖 `ObservableCollection<ClipboardItemViewModel>`，
不需要窗口就能构造断言（这正是它独立成文件的原因，见 [01 篇 §4.3](01-架构设计.md)）。

**Win32 剪切板监听（2）**：注册 / 注销 `AddClipboardFormatListener`。

**全局热键（1）**：`Ctrl+Shift+V` 可注册（被占用时记录警告并降级，仍视为流程通过）。

**Win+V 低级键盘钩子（3）**：挂载 `WH_KEYBOARD_LL`；挂载后处于运行状态；卸载后回到未运行状态。

### shoot-pages.ps1 用法

```powershell
# 先以隔离数据目录 + 演示数据启动（别写进真实历史）
$env:LIGHTCLIPBOARD_HOME = "$env:TEMP\LightClipboard-Shots"
Start-Process .\bin\Debug\net10.0-windows\LightClipboard.exe -ArgumentList '--demo'
# 再重拍
pwsh -File tools\shoot-pages.ps1
```

脚本会依次选中「全部 / 😀 Emoji / 设置」并各截一张，最后切回历史页。
找窗口用的是"类名以 `HwndWrapper` 开头 + 标题精确等于 `LightClipboard`"，避免抓到 `#32770` 对话框。

> **截图目录只放行了 5 个已知文件名**（v1.2.4 起 4 张 + v1.3.0 加拍 1 张，见 `.gitignore`）：
> `tools/shots/*.png` 被忽略，只有 `v12-emoji/history/narrow/settings.png` 与 `v13-multiselect.png`
> 这 5 个名字例外。原因是**隐私**：
> `shoot-pages.ps1` 与 `ui-flow.ps1` 默认就写到 `tools/shots/`，如果对着**没有隔离数据目录**的实例截图，
> 真实剪切板内容会被截图带进仓库。所以：
> 1) 拍真实实例前**务必**先设 `LIGHTCLIPBOARD_HOME` 指向 `%TEMP%` 下的隔离目录（上面的示例就是这么做的）；
> 2) 想提交**新名字**的截图（如 `v13-history.png`），用 `git add -f` 显式放行，否则它不会出现在 `git status` 里。

### ui-flow.ps1 用法

```powershell
pwsh -File tools\ui-flow.ps1 -Script "动作;动作;动作" [-OutDir 截图目录] [-ProcessName LightClipboard]
```

动作之间用 `;` 分隔，坐标是**屏幕物理像素**（脚本会先 `SetProcessDPIAware`）：

| 动作 | 说明 |
| --- | --- |
| `hover:X,Y` | 移动光标到坐标（触发悬停、ToolTip） |
| `click:X,Y` | 左键单击 |
| `wheel:X,Y,Delta` | 滚轮（正数向上） |
| `drag:X1,Y1,X2,Y2` | 按住左键从 (X1,Y1) 拖到 (X2,Y2) 并释放（24 步平滑移动） |
| `hotkey:M1,M2,Key` | 组合键，虚拟键码。`hotkey:17,16,86`=Ctrl+Shift+V，`hotkey:27,0,27`=Esc |
| `type:text` | 逐字符发送 ASCII（用于搜索框等）。**v1.2.2 起呼出面板不再自动聚焦搜索框**，要用它输入得先 `click` 点中搜索框（或先发 `hotkey:17,0,70` = Ctrl+F） |
| `sleep:毫秒` | 等待 |
| `shot:文件名.png` | 截取应用窗口（截图存到 `-OutDir`） |
| `rect` | 打印窗口当前矩形与可见性 |
| `visible` | 打印窗口可见性与前台进程号 |
| `foreground` | 打印前台进程号 |
| `focus:进程名` | 把某进程的窗口切到前台 |
| `notepadtext` | 打印记事本窗口句柄（或提示未运行），用于早期记事本粘贴验证 |
| `clip` | 打印当前剪切板内容 |
| `target` | 打印 WinForms 粘贴目标收到的文本 |

示例：

```powershell
# 三张页面截图
pwsh -File tools\ui-flow.ps1 -Script "shot:history.png;click:2160,785;sleep:700;shot:emoji.png;click:2236,785;sleep:700;shot:settings.png"
# 注意：上面这组坐标是 v1.1.0 的旧导航布局（两组胶囊），v1.2.0 改版后已失效，重新量一次即可

# 端到端验证"复制 + 自动粘贴"
Start-Process pwsh -ArgumentList '-NoProfile','-File','tools\paste-target.ps1'
pwsh -File tools\ui-flow.ps1 -Script "click:540,400;sleep:600;hotkey:17,16,86;sleep:500;click:2228,852;sleep:2000;target"
```

> 坐标依赖窗口位置：面板默认贴在**光标所在显示器**工作区右下角，窗口尺寸可能被
> `settings.json` 记住。稳妥做法是先跑一次 `rect` 拿到真实位置再算坐标。

### 用 UI Automation 驱动顶部胶囊（v1.2.0 起推荐）

顶部胶囊的坐标会随窗口位置变化，直接点坐标很脆；用 UI Automation 按**名字**选中更稳
（本机实测可用，`Add-Type -AssemblyName UIAutomationClient, UIAutomationTypes`）：

```powershell
$root = [System.Windows.Automation.AutomationElement]::FromHandle($hwnd)   # $hwnd 用 EnumWindows 按类名找主窗口
$cond = New-Object System.Windows.Automation.PropertyCondition(
    [System.Windows.Automation.AutomationElement]::ControlTypeProperty,
    [System.Windows.Automation.ControlType]::RadioButton)
($root.FindAll([System.Windows.Automation.TreeScope]::Descendants, $cond) |
    Where-Object { $_.Current.Name -eq '全部' } | Select-Object -First 1).
    GetCurrentPattern([System.Windows.Automation.SelectionItemPattern]::Pattern).Select()
```

两个坑：

1. **必须按"类名以 `HwndWrapper` 开头 + 标题为 `LightClipboard`"来找主窗口**。
   只按标题找会抓到 `#32770` 对话框（例如"清空历史"的确认框），量出来的矩形完全不对。
2. `SelectionItemPattern.Select()` 只改 `IsChecked`，**不会触发 `Command`** ——
   正因为如此，v1.2.0 的导航落地才必须挂在 `Checked` 事件上（坑点 9 ⚠️B）。
   也意味着用这个方法能真实复现用户点击的效果，适合做回归。


验证的是"拖出（把卡片拖到别的程序）后自动隐藏"这条收尾逻辑（`MainWindow.OnListPreviewMouseMove` /

| 用例 | 动作 | 断言 |
| --- | --- | --- |
| `accept` | 卡片 1 → 接收方文本框中央，正常松手 | 接收方收到该条文本、面板已隐藏、日志出现 `拖出成功，面板已自动隐藏` |

| `off` | 把 `settings.json` 的 `HideOnDeactivate` 改成 `false` 后**重启**应用 | 拖出后面板**保留**（日志出现 `「失焦即隐藏」已关闭`）、点击面板外也**保留**、日志里没有 `面板已自动隐藏`；**反向对照**：此时把同样置顶的接收方摆到面板上并点击，面板确实会被压住（证明 `ontop` 那条不是空断言） |
| `ontop` | 再把 `KeepOnTopWhenUnfocused` 改成 `true` 后重启 | 同样置顶的窗口盖上来后：面板被抬回最上层（`WindowFromPoint` 判定）、日志出现「始终置顶」记录、**前台仍是那个窗口**（`SWP_NOACTIVATE` 没抢焦点） |

四个实现要点：

1. **每例先 `Set-Clipboard` 一条已知文本并等 2 秒**，让卡片 1 就是本次要拖的内容 ——
   这样"接收方收到了什么"可以按值断言，不依赖演示数据的顺序。
2. **卡片坐标按面板矩形 + DPI 缩放算**（面板顶部往下 176 DIP、横向居中），不写死屏幕坐标；
   脚本还会先把光标移回主屏中部再呼出面板，让面板稳定落在同一位置。
3. **让面板处于前台再断言"点击别处会收起"**：`Ensure-PanelForeground` 只在面板不是前台时按一次
   `Ctrl+Shift+V`（可见且聚焦时按热键反而会收起面板），否则断言会在"面板本来就没聚焦"的情况下空过。
4. **`off` / `ontop` 用例必须重启应用**：设置只在启动时读一次，改 `settings.json` 后不重启等于没改；
   "遮挡"场景靠 `Cover-PanelWithTarget`：把接收方缩放到比面板大一圈，再点"面板之外、接收方之内"的位置 ——
   既激活了对方（置顶窗口被激活后排到置顶层最上面），又不会点到面板自己。

> **能力边界**：这里用自建接收方窗口而不是真记事本 —— 断言需要"确定会接受 `UnicodeText` 的目标"，
> 而记事本的可拖放区域与窗口位置随版本变化。发版前的真实链路仍建议人工拖一次到资源管理器 / 记事本。

> 顺带记下的环境坑：做真机验证时踩过一次 **OLE 会话级锁** —— 所有进程的 `DoDragDrop` 都抛
> `COMException 0x80004005 拖动操作已在进行中`，成因是另一个进程的拖拽循环卡死没退出。
> 症状与"本程序拖拽坏了"完全一样：**先确认是不是整个桌面都拖不动**（随便拖个文件试试），
> 别急着改代码；结束掉卡死的进程即可恢复。

## 6. 故障排查

| 现象 | 排查方向 |
| --- | --- |
| 面板呼不出来 | 热键是否被占用（设置页「关于」显示的组合）；托盘图标是否在溢出面板里；日志有没有"所有候选全局热键均注册失败" |
| 设置页没有「Win+V 拦截」、按 Win+V 仍弹系统面板 | 先看设置页「关于」的版本号是不是 v1.1.0 以上 —— 十有八九是跑了旧 exe（只 build 了 Debug 却在运行 Release 产物）；再看日志有没有 `[KeyboardHookService] 已挂载低级键盘钩子` |
| **只在某个程序里按 Win+V 弹系统面板 / 拖文件进去面板会消失** | 该程序是否**以管理员权限运行**。UIPI 会丢弃低权限进程的钩子回调，这是架构边界不是 bug —— 见 [10-高权限窗口支持决策记录.md](10-高权限窗口支持决策记录.md)（Everything 即此例） |
| 呼出面板后直接打字没反应 | **v1.2.2 起的预期行为**：光标不再自动落在搜索框，`OnPreviewTextInput` 也已删除 —— 先按 `Ctrl+F` 或点一下搜索框再打字（`tools/panel-focus-test.ps1` 可自动核对）。按了 Ctrl+F 仍打不了字，再往 UIPI 方向排查：按键时前台窗口可能是管理员权限程序（阻止抢焦点），代码侧看 `EnsureForeground` / `_showInProgress`（坑点 17.3 / 17.4） |
| 按 Win+V 后开始菜单弹出来 | 哑键注入被破坏（`SendDummyKey` 或 `_injecting` 被改动，坑点 17.2） |
| 复制没进历史 | 是否处于"暂停监听"；日志有无 `CLIPBRD_E_CANT_OPEN` 重试记录；`ClipboardWriter.IsSuppressed` 是否长时间为真 |
| 截图卡片是全透明 | 检查 `MakeOpaque` 是否被绕过（坑点 3） |
| 图片入库慢/界面卡 | 日志出现"后台保存图片失败，改为同步保存" → `Normalize` 被绕过（坑点 4）。注意日志级别是定长 5 字符，检索用 `Select-String '\[WARN'` |
| 点卡片没粘上 | 目标程序是否管理员权限（UIPI）；日志里"准备粘贴到 0x…（激活=成功/失败）"与"已发送 Ctrl+V"是否成对出现 |
| **点卡片后按 Ctrl+V，出来的是刚点的那条而不是列表顶部那条** | 输出后的剪切板还原没生效。三条线索：日志有没有 `已存下输出前的剪切板快照`（抓快照）与 `粘贴已送达，将在 300 ms 后…`（安排了还原）；有 `[WARN ] 剪切板还原失败` 说明还原写入被占用或载荷类型不对（坑点 19.2 那种 `InvalidCastException`）；一行都没有则是 `MainWindow.OnPasteRequested` 里的 `ScheduleRestoreAfterPaste` 没接上（另一种"没有还原记录"是正常情况：`SendInput` 没发满 4/4，日志会出现 `Ctrl+V 未发出，跳过粘贴后的剪切板还原`，此时内容**刻意**留在剪切板里让你手动 Ctrl+V）。回归用 `tools/restore-clipboard-test.ps1`，自检里另有「输出后剪切板还原（借一次就还）」22 项 |
| **我只想反复粘贴某一条，但按 Ctrl+V 总是列表顶部那条** | 这是 v1.2.4 起的**预期行为**（系统剪切板 ≡ 列表顶部）。要"拿某一条去反复粘贴"用卡片上的 ⧉ 或右键「复制」——「只复制」这条路刻意不还原 |
| 面板不自动隐藏 | 设置里关了"失焦自动隐藏"；或鼠标键正处于按下状态（延迟隐藏中）；或设置页把「隐藏延迟」调得很大 |
| **拖到别的程序并放下后，面板不自动收起** | 拖出收尾是否被删（`OnListPreviewMouseMove` 里的 `HideAfterDragOut()` 调用，坑点 6.1；`tools/dragout-test.ps1` 可自动核对）；另外确认设置页的「失焦即隐藏」没被关掉 —— 关闭时拖出同样不收起（这是有意设计） |
| **「失焦即隐藏」关了还是会收起面板** | 先确认**跑的是哪份产物**：本项目很容易在本机留下多份副本（真机实测踩过 —— 开机自启指向的是仓库之外另一个目录里的 `bin\Debug`，而改动在本仓库），判断依据是日志里有没有 `[设置] 失焦即隐藏 = 关闭`（切开关时写）与 `拖出成功，但「失焦即隐藏」已关闭，面板保持显示`（拖出时写）；两行都没有说明跑的是旧产物。三条自动收起路径是否都复查了开关，见坑点 6.2，回归用 `tools/dragout-test.ps1` 的 `off` 用例 |
| **关了「失焦即隐藏」，可面板点一下别的窗口就"消失"** | 多半不是隐藏而是**被压住**：面板本身是 `Topmost`，只有**同样置顶**的窗口（全屏/最大化浏览器、播放器、其它置顶工具）能盖住它。开设置页的「始终置顶」（`KeepOnTopWhenUnfocused`，需先关掉「失焦即隐藏」）即可；判定方法：`tools/dragout-test.ps1 -Mode ontop`，或看日志有没有 `「始终置顶」：失焦后已把面板抬回最上层`。详见坑点 6.3 |
| 面板**收得太快**，来不及去点它 | 把设置页「隐藏延迟」调大（v1.2.0 起可调，范围 50–1000ms） |
| 无法把文件拖进面板 | 面板可能已隐藏；确认延迟隐藏逻辑未被改动（坑点 6）；若拖拽起点是提权程序，见上面那条 UIPI 边界 |
| 点了顶部胶囊没反应 | `Checked="OnMainChipChecked"` 与 `Tag` 是否被删（坑点 9 ⚠️B）；**不要**试图给胶囊加 `Command`（坑点 9 ⚠️A） |
| 中文提示显示成方块 | 某个样式给控件设了图标字体，ToolTip 继承了它（坑点 8） |
| 滚动条压住内容 | 内容是否缺少右侧 `Margin`（坑点 7） |
| **设置页某行的说明文字被右侧开关盖住半行** | 该行标题列缺少 `SettingRowLabelStyle`（`Margin="0,0,56,0"`）——开关是"压在"文字上而不是"挤开"文字。注意这条**不是某个尺寸才有**：同一份代码的余量会在明显压上与刚好擦过之间跳，别按单次截图下结论，跑 `tools/settings-layout-test.ps1`（坑点 18） |
| Release 构建报 `MSB3026/MSB3027` 文件被锁定 | 程序还在运行，先退出再构建 |

日志：`%LocalAppData%\LightClipboard\Logs\app-yyyyMMdd.log`。
