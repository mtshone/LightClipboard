## 4. 刻意没有引入的东西

| 候选 | 为什么不用 |
| --- | --- |
| SkiaSharp / ImageSharp | WPF 自带 `PngBitmapEncoder`/`BitmapDecoder` 已够用，且能少 10MB+ 原生依赖 |
| System.Drawing.Common | 与 `--demo` 的图片生成、缩略图都不需要；`Gdi+` 也不支持彩色 Emoji（见第 08 篇） |
| DI 容器（MS.DI / Autofac） | 服务数量固定、生命周期与进程一致，手写 `AppHost` 更直观 |
| WinForms | 仅为托盘引入整个 WinForms 不划算；测试脚本里的 WinForms 只存在于 `tools/`，不参与程序构建 |
| Prism / MahApps 等重型 MVVM 框架 | CommunityToolkit.Mvvm 的源生成器已覆盖全部需要 |
| SQLite | LiteDB 单文件、零配置，剪切板场景没有关系型查询需求 |
| H.Hooks / EasyHook 等钩子封装库 | 全项目只用一个 `WH_KEYBOARD_LL`，自写 P/Invoke 约 60 行就够；钩子对"回调时限 + 生命周期"极其敏感（`LowLevelHooksTimeout`、委托 GC、异步派发），封装层会把这些细节藏起来 —— 出问题时更难定位（见 [04 坑点 17](04-实现细节与坑点.md)） |

## 5. 依赖升级注意事项

1. **WPF-UI**：本项目依赖的资源键（`CardBackgroundFillColorDefaultBrush`、`TextFillColorPrimaryBrush`、
   `SubtleFillColorSecondaryBrush`、`AccentFillColorDefaultBrush`、`SolidBackgroundFillColorSecondaryBrush`、
   `TextOnAccentFillColorPrimaryBrush` 等）与控件 API（`FluentWindow`、`TitleBar.ForceShutdown`、
   `ToggleSwitch`、`SymbolIcon`、`TextBox.PlaceholderText`）在 4.x 内可用。大版本升级前先跑
   `dotnet build` + 截图核对三张页面。
2. **CommunityToolkit.Mvvm**：升级后确认源生成器仍产出 `XxxCommand`；若改名，XAML 里的
   `{Binding XxxCommand}` 会静默失效（不报错、按钮不响应），务必点一遍卡片与按钮。
3. **LiteDB**：升级前先备份 `%LocalAppData%\LightClipboard\clipboard.db`。跨大版本可能不兼容旧文件格式；
   若升级，先跑 `--selftest`（含存储读写与裁剪断言）。
4. **H.NotifyIcon.Wpf**：只用到 `TaskbarIcon` 的 `IconSource`/`ToolTipText`/`ContextMenu`/
   `TrayLeftMouseUp`/`ShowNotification`/`ForceCreate`/`Dispose`。升级时重点验证托盘图标能出现、
   右键菜单能弹出。
5. 升级后**必须**执行的验证：`dotnet run -- --selftest`（50 项）+ 三页面截图 + 一次真实的
   复制→点击卡片→粘贴链路（见 [07-构建发布与测试.md](07-构建发布与测试.md) 第 5 节）。

## 6. 离线/内网还原

所有包都已存在于本机 NuGet 缓存（`%USERPROFILE%\.nuget\packages`）。内网机器可：

```powershell
# 有网机器上打包离线源
dotnet restore
Get-ChildItem "$env:USERPROFILE\.nuget\packages" -Directory | ForEach-Object { ... }  # 或直接拷贝整个 packages 目录

# 目标机指定本地源
dotnet restore --source D:\offline-nuget
```

`Microsoft Visual Studio Offline Packages` 这个默认源在某些机器上会拖慢还原，可在
`NuGet.config` 中移除。
