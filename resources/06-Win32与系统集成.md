# 06 · Win32 与系统集成

本项目所有系统级能力都通过 `Interop/NativeMethods.cs` 里的 P/Invoke 完成，没有引入任何互操作封装库。
本文档说明每个 API 的用途、调用点，以及剪切板/拖拽的格式约定。

## 2. 剪切板格式矩阵

### 2.1 读取（`ClipboardDataParser.ReadCore`，按此优先级）

| 顺序 | 检查的格式 | 处理 | 产出类型 |
| --- | --- | --- | --- |
| 1 | `DataFormats.FileDrop` | 取 `string[]` 路径 | Files |
| 2 | `"PNG"`（流） | `BitmapFrame.Create(..., OnLoad)`，**保留 alpha** | Image |
| 3 | `DataFormats.Bitmap` / `DataFormats.Dib` | `Clipboard.GetImage()` → `MakeOpaque()` | Image |
| 4 | `DataFormats.UnicodeText` / `Text` | 截断到 `MaxTextLength` | Text |

要点：
- **文件优先于图片**：资源管理器里复制文件时剪切板同时带 FileDrop 与 Bitmap，按文件处理才符合直觉。
- **PNG 流优先于 DIB**：Snipping Tool 与浏览器多数会同时提供两者，PNG 画质更好且带真实 alpha。
- **DIB 必须强制不透明**：见 [04-实现细节与坑点.md](04-实现细节与坑点.md) 第 3 条。

### 2.2 写入（`ClipboardWriter`）

| 写入内容 | 提供的格式 | 备注 |
| --- | --- | --- |
| 文本 | `UnicodeText` + `Text` | Emoji 依赖 UTF-16，天然支持 |
| 图片 | `Bitmap` + `"PNG"` 流 | 默认**不**附 FileDrop，避免粘到终端时变成一串路径；设置项 `CopyImageWithFilePath` 可开启 |
| 文件 | `FileDrop` | |

所有写入都用 `Clipboard.SetDataObject(data, copy: true)` 并配 5 次重试 + 1.5s 自写屏蔽窗口。

## 3. 拖拽（OLE Drag & Drop）格式矩阵

### 3.1 拖出（`DragDropService.BuildDataObject`）

| 条目类型 | FileDrop | Bitmap | PNG 流 | 兼容目标 |
| --- | --- | --- | --- | --- |
| 文本 | — | — | — | `UnicodeText` → 记事本、浏览器、聊天框 |
| 图片 | ✔（Exports 下的稳定 PNG 路径） | ✔ | ✔ | 资源管理器/桌面（存文件）、Office（插图）、聊天软件（发文件或图） |
| 文件 | ✔ | 单张图片文件时额外提供 | — | 资源管理器、邮件客户端 |
| 单张图片文件 | ✔ | ✔ | — | 同图片 |
| **多张图片**（v1.3.0，`BuildDataObjectForImages`） | ✔（N 个 Exports 路径，顺序 = **选择队列顺序**：**有 Ctrl 参与 ⇒ 点击顺序**（其后 Shift 只在队列末尾追加扩展），**纯 Shift 区间 ⇒ 列表顺序**，v1.3.1 改口径） | **—** | **—** | 资源管理器/桌面、聊天软件、邮件客户端。**多张时只给 FileDrop**：多张里"哪一张作为位图"没有合理答案，而这类目标本来就按文件列表逐个接收；单张仍走上面的原路径（`count == 1` 时行为不变） |

> 多选拖出的入口判定在视图层（`MainWindow.OnListPreviewMouseMove`）：**已选中**的卡片 →
> 拖出整批（`ClipboardSelection.BuildDragItems()`），**未选中**的卡片 → 仍只拖这一张；
> 一张都导不出（源文件全缺失）时 `BuildDataObjectForImages` 返回 `null` → `DoDragDrop` 返回 `None` → 面板保留。

### 3.2 拖入（`DragDropService.ParseDroppedData`）

| 拖入内容 | 处理 |
| --- | --- |
| 文件（1 个或多个） | 生成 Files 记录；**若仅一个且是图片文件，额外再生成一条 Image 记录**（便于直接粘贴位图） |
| 位图 / PNG 流 | 生成 Image 记录（PNG 保留 alpha） |
| 文本 | 生成 Text 记录 |

拖入的目标窗口必须可见，因此 `MainWindow` 对"失焦隐藏"做了延迟处理，
详见 [04-实现细节与坑点.md](04-实现细节与坑点.md) 第 6 条。

## 4. 全局热键

| 项 | 值 |
| --- | --- |
| Hotkey ID | `0xA11C` |
| 首选组合 | `Ctrl+Shift+V` |
| 降级顺序 | `Ctrl+Alt+V` → `Ctrl+Shift+F12` |
| 修饰符 | 始终带 `MOD_NOREPEAT`（按住不重复触发） |
| 消息 | `WM_HOTKEY (0x0312)`，由 `HwndSource` 钩子分发 |
| 失败表现 | Win32 错误码 1409 = 已被占用；全部失败时仅托盘可用，设置页会显示"未注册" |

> 注意：`Ctrl+Shift+V` 在 Chrome/Edge 中是"粘贴为纯文本"，注册成全局热键会抢占它。这是产品取舍，
> 需要改默认值时改 `GlobalHotkeyService.Fallbacks` 的第一项即可。

### 4.1 Win+V 接管（低级键盘钩子）

`KeyboardHookService` 与全局热键是**两条独立路径**，同时生效：热键走 `RegisterHotKey`，
Win+V 走 `WH_KEYBOARD_LL`（开关为设置项 `EnableWinVHook`，默认开）。

| 项 | 值 |
| --- | --- |
| 钩子类型 | `WH_KEYBOARD_LL (13)`，`dwThreadId = 0`（全局），`hMod = GetModuleHandle(null)` |
| 触发条件 | 消息为 `WM_KEYDOWN/WM_SYSKEYDOWN` 且 `vkCode == VK_V (0x56)` 且 `GetAsyncKeyState(VK_LWIN/VK_RWIN)` 的高位为 1 |
| 屏蔽键 | 注入 `VK_NONAME (0xFC)` 按下 + 抬起（`SendInput`），重置 Shell 的 Win 键状态机，避免松手弹开始菜单 |
| 截断方式 | 回调返回 `(IntPtr)1` —— 事件不再传给钩子链下游，也不会进目标窗口的消息队列 |
| 唤起方式 | `Application.Current.Dispatcher.BeginInvoke(...)`（回调内绝不阻塞） |
| 重复抑制 | `_winVHandled` 标记，V 或 Win 抬起后复位 |
| 生命周期 | `AppHost.AttachWindow` 里按设置挂载；`SettingsService.Changed` → `ApplyWinVHook()` 实时开关；`AppHost.Dispose` 卸载 |
| 失败表现 | `SetWindowsHookEx` 返回 0 → 记错误码到日志，设置页显示"接管失败"，Win+V 回到系统原生行为 |

**⚠️ 完整性级别前提（v1.2.0 实测确认，务必先读）**：
`WH_KEYBOARD_LL` 虽名为"全局"，但**并不豁免 UIPI**。当前台窗口的完整性级别**高于**钩子进程时
（典型：Everything 以 `run_as_admin=1` 运行，本程序以普通权限运行），
**系统会直接丢弃该进程的钩子回调** —— 不报错、不抛异常，`HookCallback` 压根不会被调用，
于是 Win+V 落给 Shell，弹出的是系统原生剪切板。

实测对照（同一探针，只换前台窗口）：

| 前台窗口 | 前台 IL | 钩子进程 IL | 是否收到按键 |
| --- | --- | --- | --- |
| 探针自有窗口 | HIGH | HIGH | ✅ 收到 |
| Everything | HIGH | MEDIUM | ❌ 一个都没收到 |
| Everything 最小化后 | — | MEDIUM | ✅ 恢复收到 |

同一原因还会连带影响"抢焦点"与"接收拖放"。完整的定位过程、备选方案与代价评估见
[10-高权限窗口支持决策记录.md](10-高权限窗口支持决策记录.md)（当前决策：暂缓，按已知边界记录）。
排查这类问题的第一反应应该是**查前台窗口是不是提权的**，而不是改钩子代码。

时序（一次按键）：

```
物理 Win+V
   ↓ 低级钩子回调（UI 线程；只做判定 + 注入，远低于 300ms 上限）
IsWinKeyDown? → SendInput(0xFC↓ 0xFC↑) → BeginInvoke(唤起) → return 1
   ↓ 输入流里已经没有这个 V 了
explorer 的原生剪切板历史 / 目标窗口：都收不到 Win+V
   ↓ Dispatcher 处理 BeginInvoke
MainWindow.TogglePanel() → ShowPanel() → EnsureForeground()（前台锁定被驳回时抢一次）
   → FocusPanelWithoutCaret()（v1.2.2：焦点交给窗口本身，光标不进搜索框）
```

排障：日志里 `[KeyboardHookService] 已挂载低级键盘钩子` / `拦截到 Win+V` / `已卸载低级键盘钩子`
可确认挂载与命中；`tools/winv-test.ps1` 可自动核对"面板是否弹出、是否拿到前台焦点、再按是否收起"。

**验证边界（重要）**：`keybd_event` / `SendInput` 属于注入输入，Windows 不把注入的 Win 组合键交给
Shell 的剪切板历史处理，所以"原生面板是否被压住"**无法**用自动化脚本对照，只能真机手按 Win+V。
2026-09-19 已在真机（Win11 23H2，原生剪切板历史处于开启状态，`EnableClipboardHistory=1`，Release 构建 v1.1.0）确认：
按 Win+V 时原生面板不再弹出，改由本面板响应。

> 原理依据：`LowLevelKeyboardProc` 文档明确"回调返回非 0 时，系统不再把该消息传给钩子链的其余部分，
> 也不传给目标窗口过程"，而热键派发（`RegisterHotKey`）与 Shell 的 Win 组合键判定都发生在这之后；
> 哑键屏蔽 Win 键抬起则是 AutoHotkey `A_MenuMaskKey` 用的同一套手法。

## 5. 粘贴链路（模拟 Ctrl+V）

```
用户点击卡片
   ↓
ClipboardWriter.CaptureForRestore()     ★v1.2.4：先存下"输出前"的剪切板快照
   ↓
ClipboardWriter.SetItem(...)            写剪切板（带 1.5s 屏蔽窗口）
   ↓
MainWindow.HidePanel()                  先隐藏自己，否则会抢焦点
   ↓
PasteService.ActivateWindow(target)     SetForegroundWindow
   │                                    失败 → AttachThreadInput 兜底
   ↓
DispatcherTimer 130ms                   等前台切换真正完成
   ↓
SendInput(Ctrl↓ V↓ V↑ Ctrl↑)            4 个键盘事件
   ↓
afterPasteSent 回调（仅当 SendInput 4/4）★v1.2.4：ScheduleRestoreAfterPaste()
   ↓
DispatcherTimer 300ms                   等目标程序在自己的消息循环里把内容取走
   ↓
ClipboardWriter.RestoreNow()            ★v1.2.4：把快照写回（同样走屏蔽窗口 + 5 次重试）
```

时序参数：
- 激活成功 → 延时 **130ms**；激活失败 → 延时 60ms 后仍尝试发送；
- 还原再等 **300ms**（`ClipboardWriter.RestoreDelayMs`）：若抢在目标程序读取之前写回，
  粘贴会拿到旧内容甚至失败 —— 这段等待是"借还"能成立的前提，别调成 0；
- `INPUT` 结构实测大小 40 字节（x64），`SendInput` 返回值会与事件数比对并记录日志。

**"借还"的边界**：`SendInput` 没发满 4 个事件 → 不还原（内容留在剪切板里，用户还能手动 Ctrl+V），
日志是 `Ctrl+V 未发出，跳过粘贴后的剪切板还原`，**注意这条路径不会丢掉快照**（`HasRestorePending` 仍为 true），
快照要等下一次 `CaptureForRestore()` 开头或"只复制 / 目标窗口无效"路径才被清掉 —— 排障时别把
"没有还原日志"一律当成接线断了；
目标窗口无效（`_previousForeground` 已销毁）→ `DiscardRestore()` 不还原；
"只复制不粘贴"与"拖出"两条路径**刻意**不还原（前者的语义就是把这一条留在剪切板里）。

日志中可看到：`准备粘贴到 0x...（激活=成功）`、`已发送 Ctrl+V（SendInput 4/4，当前前台窗口 0x...）`，
以及 v1.2.4 的三行 `已存下输出前的剪切板快照：...` / `粘贴已送达，将在 300 ms 后把剪切板还原为输出前的内容` /
`剪切板已还原为输出前的内容（N 种格式）`；失败时是 `[WARN ] 剪切板还原失败：剪切板里保留的是刚输出的那条`。

## 6. 窗口与焦点策略

| 行为 | 实现 |
| --- | --- |
| 面板不占任务栏 | `ShowInTaskbar=False`（会被设置 owner，导致 `Process.MainWindowHandle` 返回 0） |
| 置顶 | `Topmost=True` |
| 定位 | 光标所在显示器工作区右下角，物理像素 `SetWindowPos`，留 12px 边距 |
| 高度上限 | 按目标显示器 DPI 换算的 `MaxHeight = 工作区高 - 24` |
| 显示时避免跳位 | 先 `Opacity=0` → `Show()` → 定位 → `Opacity=1` |
| 显示时抢焦点 | `Activate()` 后由 `EnsureForeground()` 以 `GetForegroundWindow()` 实际值复核，被前台锁定驳回时走 `PasteService.ForceForeground`（挂到前台窗口线程 + `BringWindowToTop`） |
| 呼出后的键盘焦点（v1.2.2） | `ShowPanel` 在 `Activate()` + `EnsureForeground()` 之后调 `FocusPanelWithoutCaret()`：清掉子控件逻辑焦点（`FocusManager.SetFocusedElement(this, null)`）并把焦点交给**窗口本身**（`Keyboard.Focus(this)`），**不再聚焦搜索框**。Esc / Enter / Delete / ↑↓ / Ctrl+F 全走窗口级 `OnPreviewKeyDown`，不依赖子控件焦点；搜索入口只有两个：`Ctrl+F` 或鼠标点击搜索框（`FocusSearchBox`），已无"呼出即可打字搜索"（`OnPreviewTextInput` 已删除）。每次呼出由 `MainViewModel.OnPanelShown` 清空上次关键词 |
| 显示期间的失焦 | `_showInProgress` 标记期内忽略 `Deactivated`（抢前台前会先收到一个 `WM_ACTIVATE(INACTIVE)`），延时聚焦回调里复位 |
| 记录粘贴目标 | `ShowPanel` 时用 `GetExternalForegroundWindow`（排除自身句柄）；仅在非 0 时更新 |
| 失焦隐藏的缓冲 | 失焦时若鼠标键仍按着，启动延迟计时器（`DeferredHideDelayMs`，默认 700ms、可设 50–1000ms）；期间收到 `DragEnter/DragOver` 即取消隐藏。计时器 `Interval` 由 `MainWindow.OnSettingsChanged` 实时同步设置变更（坑点 6） |
| 关闭按钮 | 拦截 `OnClosing` → 取消关闭并隐藏，程序继续驻留 |
| 真正退出 | 托盘菜单「退出」→ `Application.Current.Shutdown()`（`AppHost`）→ `App.OnExit` 里 `_window.AllowClose()` 放行 `OnClosing`（`App.xaml.cs`；`AllowClose` 定义在 `MainWindow.xaml.cs`） |

> **抢焦点同样受 UIPI 限制**：前台窗口是提权程序时，`SetForegroundWindow` 与 `AttachThreadInput` 兜底
> 都无法把面板拉到前台（日志会出现 `面板未能取得前台焦点（前台窗口可能以管理员权限运行）`）。
> 这与 §4.1 的钩子被丢弃是同一个根因，详见 [10-高权限窗口支持决策记录.md](10-高权限窗口支持决策记录.md)。

## 7. 托盘与开机自启

| 项 | 实现 |
| --- | --- |
| 托盘图标 | `TaskbarIcon`（H.NotifyIcon），`IconSource` 取 `pack://application:,,,/Assets/app.ico` 的 32px 帧 |
| 图标位置 | 新注册的图标默认落在 Windows 11 的**溢出面板**里（系统行为，无法由程序强制提到任务栏） |
| 菜单项 | 打开面板 / 热键提示（禁用态）/ 暂停监听 / 点击后自动粘贴 / Win+V 拦截 / 开机自动启动 / 清空历史 / 设置 / 打开数据目录 / 退出 |
| 勾选同步 | `TrayIconService.SyncState(settings)` 同步四个勾选项（暂停监听 / 自动粘贴 / 开机自启 / Win+V 拦截）。**目前只在面板的暂停/恢复按钮里调用**（`MainWindow.OnPauseClick`）；在设置页改这四项只写 `settings.json` 并刷新设置页自身文案，不会同步托盘勾选 —— 已知不一致，托盘勾选要等重启或点一次暂停按钮才对齐 |
| 开机自启 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值名 `LightClipboard`，内容为 `"<exe路径>" --startup`；只读判断以注册表为准 |

## 8. 插件/扩展提示

若要接入系统层面新能力，建议：
1. 统一在 `Interop/NativeMethods.cs` 增加声明（集中管理，便于审阅与安全审计）；
2. 在 `Services/` 下新建 `sealed` 服务，通过 `AppHost` 创建与释放；
3. 若需要 HWND，请用 `AppHost.AttachWindow` 的时机（窗口句柄就绪后）注册，不要在新服务里自己等窗口。
